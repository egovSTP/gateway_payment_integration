# Payment Providers API — Integration Guide

Base URL: `http://<host>:8290/payments`

All endpoints are `POST`. The `provider` field in the request body controls routing. Fields that don't apply to the selected provider can be `null` or omitted entirely.

---

## Headers

| Header | SAOWALLET | DOBRADIGITAL | Description |
|---|---|---|---|
| `Content-Type` | required | required | `application/json` |
| `clientKey` | required | required | Maps to `X-Merchant-Login` (SAOWALLET) or `x-client-key` (DOBRADIGITAL) |
| `apiKey` | required | — | Maps to `X-Api-Key` (SAOWALLET only) |
| `idempotencyKey` | optional | — | Maps to `Idempotency-Key` (SAOWALLET). Auto-generated if omitted |

---

## Unified Request Body — POST `/payments/create`

The same body is used for all providers. Required fields differ by `provider`:

```json
{
  "provider":     "SAOWALLET | DOBRADIGITAL",

  // ── common ─────────────────────────────────────────
  "amount":        550.00,          // required for all — max 2 decimal places, dot separator

  // ── SAOWALLET ──────────────────────────────────────
  "name":          "Invoice #1001", // required — invoice name
  "payerContact":  "+2399XXXXXXX",  // required — payer phone or login
  "currency":      "STN",           // required — ISO 4217 code (mapped to currencyCode internally)
  "providerId":    "INIC",          // required — SDK.Finance payment provider ID
  "description":   "Order #1001",   // optional

  // ── DOBRADIGITAL ───────────────────────────────────
  "reference":     "1133",          // required — 4-digit Dobra Digital wallet reference
  "services": [                     // required — amount allocation per service (sum must equal amount)
    { "id": "d41b5647-...", "amount": 250 },
    { "id": "f9d32bfa-...", "amount": 300 }
  ],                                // use [] if no service allocation is needed
  "duceId":        ""               // optional
}
```

Fields outside the selected provider's set are **ignored** — they do not cause errors. For example, a SAOWALLET request may include `reference` and `services` as `null` without issue.

## Endpoints

### POST `/payments/create`

#### SAOWALLET example

```bash
curl -X POST http://localhost:8290/payments/create \
  -H "Content-Type: application/json" \
  -H "apiKey: <your-api-key>" \
  -H "clientKey: <your-merchant-login>" \
  -H "idempotencyKey: order-1001" \
  -d '{
    "provider":    "SAOWALLET",
    "amount":      550.00,
    "currency":    "STN",
    "name":        "Invoice #1001",
    "payerContact": "+2399XXXXXXX",
    "providerId":  "INIC",
    "description": "Order #1001",
    "reference":   null,
    "services":    null
  }'
```

**Response** — SDK.Finance invoice object (forwarded as-is):
```json
{
  "id": "inv-abc123",
  "status": "PENDING",
  "amount": 550.00,
  "currencyCode": "STN"
}
```

---

#### DOBRADIGITAL example

```bash
curl -X POST http://localhost:8290/payments/create \
  -H "Content-Type: application/json" \
  -H "clientKey: <your-client-key>" \
  -d '{
    "provider":   "DOBRADIGITAL",
    "amount":     550,
    "reference":  "1133",
    "services": [
      { "id": "d41b5647-3cf4-4f15-a822-bcb71b61704c", "amount": 250 },
      { "id": "f9d32bfa-1fc7-4445-bfbe-c3b8c03e0ebb", "amount": 300 }
    ],
    "name":        null,
    "payerContact": null,
    "currency":    null,
    "providerId":  null
  }'
```

The gateway performs two steps internally:
1. **Lookup** — validates the wallet `reference`
2. **Start transaction** — user must approve in their Dobra Digital wallet app

**Response:**
```json
{
  "transactionId": "txn-abc123",
  "userId": "user-xyz",
  "links": {
    "sseUrl": "https://...",
    "pollUrl": "https://..."
  }
}
```

#### DOBRA24 example

`entityCode` and `reference` are generated by the caller (gateway_core owns SIBS
Entidade/Referência assignment) — this call just registers them with `gateway_spout_rta`,
which batches them into an AEPS file for dobra24/SIBS EPMS. No `clientKey`/`apiKey`
headers needed — MI authenticates to `gateway_spout_rta` with its own credential.

```bash
curl -X POST http://localhost:8290/payments/create \
  -H "Content-Type: application/json" \
  -d '{
    "provider":        "DOBRA24",
    "amount":          100.00,
    "entityCode":      "10001",
    "reference":       "000000001",
    "callerReference": "payment_abc123"
  }'
```

**Response** — the registered reference, forwarded as-is from `gateway_spout_rta`:
```json
{
  "id": "cmtk60f6t0000uaaqcjsbyjge",
  "entityCode": "10001",
  "reference": "000000001",
  "amount": "100",
  "status": "PENDING"
}
```

Unlike SAOWALLET/DOBRADIGITAL, DOBRA24 payment confirmation does **not** arrive via
`/payments/status` polling — the citizen pays at an ATM/POS on their own schedule, which
could be minutes to days later. `gateway_spout_rta` notifies `gateway_core` directly via
webhook when the payment is confirmed (outside MI entirely, same as how SAOWALLET/
DOBRADIGITAL notify `gateway_core` directly rather than through this gateway). `/status`
is still available for on-demand/reconciliation lookups.

### POST `/payments/status`

Polls the current status. `identifier` is the ID returned by `/create`.

```bash
curl -X POST http://localhost:8290/payments/status \
  -H "Content-Type: application/json" \
  -H "clientKey: <your-client-key>" \
  -d '{
    "provider":    "DOBRADIGITAL",
    "identifier":  "txn-abc123"
  }'
```

| Provider | `identifier` |
|---|---|
| SAOWALLET | Invoice ID from `/create` response |
| DOBRADIGITAL | `transactionId` from `/create` response |

**DOBRADIGITAL response:**
```json
{
  "version": "1.0",
  "timestamp": "2026-07-01T15:00:00Z",
  "transaction": {
    "transactionId": "txn-abc123",
    "status": "CONFIRMED",
    "amount": 550
  }
}
```

**Transaction statuses:**

| Status | Meaning |
|---|---|
| `CONFIRMED` | User approved — pending final settlement |
| `COMPLETED` | Fully settled |
| `FAILED` | Payment failed |
| `CANCELLED` | User or system cancelled |
| `EXPIRED` | Approval window timed out (user did not act in time) |

> Poll every few seconds until a terminal status (`COMPLETED`, `FAILED`, `CANCELLED`, `EXPIRED`) is received. Avoid excessive polling — the server may return `429 Too Many Requests`.

## Full DobraDigital Integration Flow

```
1.  Collect the user's 4-digit Dobra Digital wallet reference from your UI
2.  POST /payments/create  →  receive transactionId
3.  Show "Please approve this payment in your Dobra Digital wallet app"
4.  Poll POST /payments/status with the transactionId every ~3 seconds
5a. status = CONFIRMED / COMPLETED  →  show success screen
5b. status = FAILED / CANCELLED / EXPIRED  →  show failure, offer retry
```

## Validation

The gateway validates credentials and required fields **before** calling any provider.

### Missing `provider` field — `400`
```json
{ "error": { "code": "MISSING_REQUIRED_FIELD", "message": "Field 'provider' is required. Supported values: SAOWALLET, DOBRADIGITAL" } }
```

### Missing required body fields — `400`
```json
{ "error": { "code": "MISSING_REQUIRED_FIELD", "message": "SAOWALLET requires: amount, currency, name, payerContact, providerId" } }
```
```json
{ "error": { "code": "MISSING_REQUIRED_FIELD", "message": "DOBRADIGITAL requires: amount, reference" } }
```
```json
{ "error": { "code": "MISSING_REQUIRED_FIELD", "message": "DOBRA24 requires: amount, entityCode, reference" } }
```

### Missing credentials — `401`
```json
{ "error": { "code": "MISSING_CREDENTIALS", "message": "SAOWALLET requires headers: apiKey, clientKey" } }
```
```json
{ "error": { "code": "MISSING_CREDENTIALS", "message": "DOBRADIGITAL requires header: clientKey" } }
```

### Unknown provider — `400`
```json
{ "error": { "code": "UNKNOWN_PROVIDER", "message": "Provider 'XYZ' is not supported. Supported: SAOWALLET, DOBRADIGITAL, DOBRA24" } }
```

## HTTP Status Codes

| Code | Description |
|---|---|
| `200` | Success |
| `400` | Missing or invalid fields / unknown provider |
| `401` | Missing or invalid credentials headers |
| `404` | Resource not found |
| `429` | Too many requests — polling too fast |
| `500` | Internal server error |
| `501` | Feature not yet implemented for this provider |
